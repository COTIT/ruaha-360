Ruaha 360 · foundations

A system for saying what is known, and what is only estimated

Same four brand colours, same Poppins, same four weights, same no-shadow depth model. What is new is that each has a defined scale and a named set of tokens, so thirty screens stop being assembled out of ad-hoc opacities. Every rule below exists to protect a product-language distinction: planned not measured, prospective never summed with approved, an estimate labelled an estimate, an opportunity that is not a sale.

00 · Brand mark

The Ruaha Energy lockup, and where the product name sits next to it

The supplied SVG lockup replaces the text brand in every header. Ruaha 360 is a programme surface, not a second brand — so the lockup stays whole and 360 follows it after a hairline divider, in the interface's own type rather than as a logo of its own. The mark's blue and green are the same #1d70b7 and #93c01f the interface is built on, which is why the tokens need no adjustment.

03 · ProvenanceBadge

One object, two segments: where it came from, and whether anyone checked

Three loose text chips read as noise because the three are equal in weight, so the eye has nothing to scan. Here the source is a quiet tinted segment with a colour cap; the verification is the loud segment, with a mark whose shape differs as well as its colour — so a column of records can be read for state alone, at a glance, and verified can never be mistaken for unverified.

04 · StatusPill

Three vocabularies, and a decision never looks like a conversation

A request's Approved is a decision: solid green fill. An opportunity's Accepted means both sides agreed to keep talking: outlined, never filled. Terminal-but-inert states (withdrawn, lapsed, cancelled) are hatched. Nothing in the opportunity row is allowed to read as strongly as the request row.

Request

Draft Submitted Under review Approved Rejected Withdrawn

Only Approved gets a solid brand fill. It is the only state in the system that is a decision with capacity consequences.

Demand

Open Matched Closed Cancelled

Matched is a tint, not a fill: supply was found, nothing was sold.

Opportunity

Proposed Shared Accepted Declined Lapsed

Every opportunity pill is outlined on white. Accepted is distinguished by a heavier edge, not by a fill — it is not an approval.

06 · States

Empty is an answer. Error is a failure. They must not rhyme

Row-level security returning nothing means "you may not see this" — never red, never a retry. An error carries role="alert", a red rule, the database's sentence verbatim, and room for two technical lines without truncation.

Empty · zero rows

No matching supply

No village has available supply of this crop in this window. That is an honest zero, not a missing row.

Error · something failed

Loading · flat blocks, no shimmer

On 3G this is what the farmer surface shows most often. Flat blocks, no shimmer and no pulse — an animated skeleton repaints every frame on a phone that has better things to do. It holds the shape of what is coming, and tile-drill stays dimmed text until the figure lands.

Designed for the translated build, not the English one

557 of 559 strings still render English through the fallback. Below, chrome labels are pseudo-localised at roughly +30% — a length test, not Kiswahili; no product string here was invented. Crop and equipment names are the real database values a Swahili-locale user already sees.

Buttons wrap, never clip

09 · Icons

Lucide, already installed — no new dependency

lucide-react@1.43 is in package.json and components.json names "iconLibrary": "lucide", so the icon set is a decision already made — nothing is added. Interface icons are 18–22px at stroke 2 (2.25 on the active state, so weight tracks the label). Icons never appear alone in navigation: icon plus label, because a Kiswahili-first surface cannot rely on a glyph nobody has been taught.

Where icons are allowed

Yes: nav destinations (with label), Tower tile headers, queue cards, the Verify and Register actions, drill and back links.

No: table cells, status pills, provenance. Those already carry a shape system — a source cap, a verification mark, a confidence meter — and adding a second glyph vocabulary on top of it would undo the work of §03.

Never icon-only in navigation or on a destructive control. A tooltip is not a label on a phone.

Sizes, and the marks they must not collide with

The verification marks are filled discs and rings, not stroked Lucide glyphs — deliberately a different visual class, so a state mark is never mistaken for a control.

Where a unit mark goes, and where it does not

Yes: the label above or beside a headline figure, a table column header, a legend row, the result of an equation line. No: inside every table cell — twenty repeated glyphs down a column is the noise problem the provenance badge already had, and it breaks tabular alignment. One mark in the header does the same work for the whole column.

11 · Bars and meters

Three ways to tell two segments apart, not one

There is no chart library and none is coming, so every graphic here is a CSS bar. Each segment is distinguished by fill, pattern and a legend row carrying its own icon and figure — never by colour alone. Bars are 16–18px tall so a segment is visible on a small, scratched screen in sunlight, and every bar states its own total.

Anatomy

Coverage of 9,000.00 kg62.2%
Solid = available now5,600.00 kg
Hatched = not covered3,400.00 kg
Outlined, below the rule = committed6,400.00 kg

Solid means real and available. Hatched means missing or provisional. Outlined means it exists but is spoken for — and it is drawn outside the track, because it is not part of what the bar measures.

Ratio meters · data quality

Persons verified3 / 6
Farms with GPS3 / 4

A ratio is always written as n / total beside its bar. A percentage alone hides how few records the share is drawn from.

Never

One bar holding prospective and approved. One bar summing available and committed. A donut, a sparkline, or any figure without its unit — those need a library, and there is not one.

Performance rules this design commits to

No animation, no transition, anywhere. No fades, no slides, no shimmer, no spinner sweep. A state change is a repaint, not a performance.

No blur, no filter, no box-shadow. Depth stays borders and the white-on-sand contrast — all of it cheap on a low-end GPU.

No images. Icons are inline SVG paths from the Lucide package already installed; hatching, marks and meters are CSS gradients and borders. Nothing new is downloaded on a 3G connection.

No new fonts. The four Poppins latin weights already subset are the whole type system.

Fixed skeleton footprints. Loading blocks match the height of what replaces them, so a tile landing does not reflow the grid — the cheapest kind of fast is a layout that never moves twice.

Everything above is Tailwind-expressible against the existing @theme block: three ink values, three surfaces, one hatch, six spacing steps, eight type steps. No new dependency, no chart library, no icon package — the marks, meters and hatches are CSS. No dark palette is defined.
